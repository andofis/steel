# 海康四相机钢管图像采集控制台

控制台负责四台海康线阵相机的采集和圆柱展开。实时采集线程不运行深度学习推理；归档后可单独复核孔洞（见“展开切口与孔洞复核”）。不包含 PLC 分拣或流水线判定。

## 硬件配置

- 相机：海康机器人 `MV-CL024-91GM` 线阵黑白相机
- 数量：4 台
- 接口：GigE
- MVS：已安装 `MVS 5.1.1`
- SDK：已安装 `MVS SDK Development 4.9.0.3`
- 光电开关接入每台相机的 `Line0`
- 触发极性默认：低电平有效

固定通道与序列号映射：

| 通道 | 序列号 |
| --- | --- |
| `cam_0` | `DB0959183` |
| `cam_90` | `DB2692106` |
| `cam_180` | `DB0426965` |
| `cam_270` | `DB0426961` |

## 启动方式

双击：

```text
启动海康采集控制台.bat
```

程序会初始化海康 MVS SDK，并打开：

```text
http://127.0.0.1:8765
```

关闭启动窗口即可停止采集服务。

运行需要：

- Windows 10/11 64 位
- Python 3.10 或更高版本
- `numpy` 和 `opencv-python-headless`
- 海康 MVS 客户端及 SDK Development
- MVS 的 Python `MvImport` 文件

程序会自动查找以下安装位置：

```text
E:\MVS\Development\Samples\Python\MvImport
C:\Program Files\MVS\Development\Samples\Python\MvImport
C:\Program Files (x86)\MVS\Development\Samples\Python\MvImport
```

以及对应 MVS Runtime 目录。

## 操作流程

1. 打开 MVS 客户端，确认四台相机都能被枚举。
2. 双击 `启动海康采集控制台.bat`。
3. 点击“刷新”确认显示 `4 / 4 在线`。
4. 点击“全部连接”。
5. 点击“开始实时预览”，调整曝光、增益和行频。
6. 点击“应用到四台相机”。
7. 点击“开始触发采集”，进入光电触发等待状态。
8. 每来一根钢管，四台相机完成采集后调用 `tube_unwrap` 模块生成圆柱展开图，并自动保存五张图片：

```text
captures/
└─ pipe_20261112_171230_123/
   ├─ cam_0.png
   ├─ cam_90.png
   ├─ cam_180.png
   ├─ cam_270.png
   ├─ unwrapped.png
   └─ capture.json
```

四张 `cam_*.png` 保存相机实际采集的完整拼接图。`unwrapped.png` 由 `tube_unwrap` 按 `cam_0 → cam_90 → cam_180 → cam_270` 顺序生成。配方参考尺寸是 `1536 × 10000`；本项目初始选用均衡档 `1152 × 7500`。`capture.json` 的 `parameters.unwrap_size` 记录该根钢管触发时选定的尺寸，`unwrapped.width/height` 记录实际输出。

### 选择展开图尺寸

在控制台右侧的 **展开图尺寸** 选择档位，然后点 **保存展开尺寸**。也可选择 **自定义宽高**，分别输入宽（圆周）和高（管长）。当前配方支持宽 128–1536、高 128–10000 的整数像素。两边使用相同比例可避免孔的外形被拉伸。更小的图不一定还能辨认最小孔，切换生产档前请用已知样本核对。

| 档位 | 宽 × 高（像素） | 相对原档的像素量 | 展开中位数 | 从四路整图在内存到网页显示的中位数 |
| --- | --- | --- | --- | --- |
| 原尺寸 | 1536 × 10000 | 100% | 393 ms | 605 ms |
| 均衡 | 1152 × 7500 | 56.25% | 318 ms | 460 ms |
| 快速 | 768 × 5000 | 25% | 267 ms | 367 ms |
| 小图 | 384 × 2500 | 6.25% | 235 ms | 284 ms |

上表为本机 20 组现场原图逐档预热回放（2026-11-21）。网页一列使用真实 Edge 页面，计至本批图像加载并经历两次动画帧回调；不含实际采集、管尾补采及深度学习识别。原尺寸的 20 张图与修改前逐像素相同。四个档位的几何候选孔数一致，不代表小孔在所有分辨率下仍有相同的模型检出率。

新尺寸从**下一根触发采集的钢管**开始生效。正在采集、排队或已经归档的钢管不变；不重启相机，不改行频，不缩小四路原图。选择保存在 `settings.json`；旧配置没有此项或尺寸超出当前配方时，使用配方原尺寸。算法直接按所选网格展开和编码，不先生成大图。孔洞候选的分组和管尾裁剪在参考坐标中判断，再映射到所选尺寸，兼容跨圆周接缝的孔。

## 连续采集和本次运行记录

点击“开始触发采集”后不需要再次停止采集才能保存。每根钢管离开光电开关并完成尾部补采后，系统会自动：

1. 拼接四路钢管图
2. 直接按该根管选定的尺寸生成展开图，在内存中发布无损 PNG 给控制台
3. 以同一份编码数据归档 `unwrapped.png`，再并行保存四张完整原图
4. 继续等待下一根钢管

页面下方“本次运行采集记录”会记录每个批次：

- 序号
- 文件夹名称
- 文件夹内实际图像数量
- 采集是否完整、展开是否成功
- 完成时间
- 本次运行的文件夹数、图像总数和钢管总数

## 展开结果查看

采集和展开完成后，控制台通过结果通知自动切换到顶部的“展开结果”页签。显示的是与归档逐字节相同、按所选尺寸生成的 PNG，但不等文件写完。图像请求带批次号；旧批次的迟到请求不会拿到另一根管的图。通知中断时，常规状态刷新仍可取图。该页面支持：

- 放大、缩小和恢复适应宽度
- 查看结果尺寸、处理耗时和钢管批次号
- 一键打开图像保存目录
- 再次点击“单路监看”或“四路监看”即可返回相机画面

服务重启后，会从最近保存的批次中恢复最新展开图，不需要重新采集才能查看。

## 采集与展开时间轴

每根钢管处理完成后，运行日志会新增两条记录：

- `采集时间轴`：列出光电触发、钢管离开、收尾开始、帧拼接、保存开始、四图写盘、展开完成、展开图写盘、`capture.json` 完成等阶段的时间戳
- `采集耗时`：列出触发到最后帧、最后帧到收尾、图像拼接、保存排队、四图写盘、展开算法、展开图写盘和总处理耗时

完整时间戳同时写入该钢管目录下的 `capture.json`：

```text
中文摘要                    批次、采集时间、展开状态和输出尺寸
处理时间轴.触发到展开图可见   兼容旧名称：从触发到后端已发布、浏览器可取图，不含浏览器绘制
处理时间轴.四路记录末帧到可取图  从最后一路记录的末帧到发布；末帧可能含尾部空白，不等于物理管尾
处理时间轴.全部处理总耗时     全部文件保存完成的总耗时
处理时间轴.阶段[]            阶段名称、时间和耗时
处理时间轴.四路相机采集明细   相机首帧、末帧、帧数和拼接行数
```

后端只缓存最新一根的编码图，复用现有保存线程，不另设归档队列。内存出图和磁盘归档是两件事：归档失败时保留当前图供查看，界面和采集记录单独报错，未写成的文件不计入保存张数。重启后仍从已归档的文件恢复。

展开算法运行期间会自动暂停四路实时预览更新，保留最后一帧；相机取流、光电触发和下一根钢管的采集继续运行。预览任务排空后，展开借用一个空闲预览线程，把四路管身定位分为两组；相机的拼接顺序和几何参数不变。展开成功或失败后恢复预览；多根钢管同时展开时，待所有展开任务结束再恢复。

### 速度复测（不接相机）

在工程目录运行以下命令。参数是包含各批 `capture.json` 和四路 PNG 的目录。脚本不加载相机 SDK、不使用现场保存目录，只在临时目录归档；输出每批展开图解码像素的 SHA-256、候选孔数及各阶段耗时，可对同一批输入复测。

```powershell
.\.venv\Scripts\python.exe .\tools\replay_speed.py "D:\现场采集样本" --limit 20
.\.venv\Scripts\python.exe .\tools\replay_speed.py "D:\现场采集样本" --limit 20 --size 768 5000
```

回放不读取或覆盖控制台选择；不带 `--size` 时按配方原尺寸运行。下面两项历史对照也使用原尺寸。

2026-11-21 本机（i7-12650H）验证：对 AOX、B1、B2、未分类1 各 5 组，在同一台电脑上预热后回放。旧版 `a7d2b42` 与新版的 20 张展开图逐像素相同，四路归档原图与输入逐像素相同。另用实际 Edge 页面测了从四路整图已在内存到图像加载、经历两次浏览器动画帧回调的时间：旧版中位数 1.77 秒、最慢 2.32 秒；新版两轮中位数分别为 0.60 和 0.59 秒，最慢分别为 0.73 和 0.78 秒。脚本只测后端，不会代替上述浏览器测量。以上均不含真实光电、管尾补采和深度学习识别，不能据此判定整管检测已达标。

另从四类中各取 2 组，按 256 行拆包，模拟最后一批帧进入真实回调，让系统自行组帧和调度展开。从这批回调入口到网页显示，中位数由 1.57 秒降到 0.60 秒。该实验不模拟从有效管尾到末帧之间的补采等待。

## 让四路钢管几何尺寸一致

软件不对图片做缩放。长度和宽度应在相机侧调整：

- 长度方向：四台相机的目标行频必须一致。当前四路均设置为 `3300 Hz`
- 宽度方向：四台相机应使用相同焦距镜头、相同工作距离，并保持光轴垂直对准钢管
- 相机内应保持相同的 `Width`、`OffsetX`、Binning 和 Decimation 设置
- 曝光和 DigitalShift 只控制亮度，不会改变钢管实际成像宽度和长度
- 如果某一路固定少 `256` 行，通常不是相机参数错误，而是最后一帧尚未到达。软件会等待“四路对齐等待”参数设定的时间，直到四路行数一致后再保存

界面中的参数均可手动修改。本型号的 `GainRaw` 上限接近 `0 dB`，软件实际使用相机的 `DigitalShift` 数字增益节点；`0 dB` 不改变亮度，`+6 dB` 约提高一倍，`+12 dB` 约提高四倍。输出目录和文件夹前缀为全局保存设置。

## 网络要求

四台 GigE 相机必须与电脑网卡处于可通信的同一网段。建议为相机专口设置静态 IP，例如：

```text
电脑：192.168.1.100 / 255.255.255.0
相机：192.168.1.11 ～ 192.168.1.14
```

并设置：

- 巨帧：`9014` 或 `9000`
- 关闭该网卡的节能休眠
- Windows 防火墙允许 `MVS.exe` 和 `python.exe`
- MVS 客户端中能正常看到四台相机

如果 MVS 客户端显示“无设备信息”，本软件同样无法连接。先用 MVS 或 `Ip_Configurator.exe` 配置相机 IP。

## 触发说明

软件使用海康线阵相机的 `FrameScan` 模式：

- `FrameTriggerMode = true`
- `FrameTriggerSource = Line0`
- `TriggerActivation = LevelLow`
- `AcquisitionLineRate = 4100 Hz`
- 每台相机完成一帧后通过 SDK 回调交给保存线程
- 四路帧按到达时间归入同一根钢管，并保存到独立目录

“头部延迟”会尝试写入相机的帧触发延迟节点。“尾部补采”“无料确认时间”和“四路对齐等待”参与软件端批次等待与收尾；不同相机固件的 Line0 门控行为可能略有差异，正式投产前需要用实际钢管运动完成一次标定。

## 故障排查

### API 显示 MVS SDK 就绪，但 0 / 4 在线

1. 打开 MVS 客户端并点击刷新。
2. MVS 仍显示无设备时，检查相机 12～24V 或 PoE 48V 供电。
3. 检查网线与 PoE 交换机端口指示灯。
4. 检查电脑网卡 IP 与相机 IP 是否在同一网段。
5. 运行诊断：

```text
python diagnose_cameras.py
```

该脚本会输出 SDK 版本、枚举返回码、相机型号、序列号与 IP。

### 相机在线但预览黑屏

- 点击“开始实时预览”
- 检查曝光是否过低
- 检查镜头光圈和光源
- 在 MVS 中先确认能正常取流

### 能触发但没有保存

- 确认状态为“等待光电触发”
- 检查 Line0 光电信号电平
- 降低行频或检查触发极性
- 查看界面右下角运行日志
- 检查 `captures` 目录是否可写

## 展开切口与孔洞复核

**实时展开：** 默认 `tube_unwrap_recipe.json` 的 `panorama_seam` 为 `auto`。四路相机仍在标定坐标下展开、融合；发布前才检查各高度孔候选轮廓的圆周范围。原切口已有约 1/64 圆周的净空时保持不动；否则选离所有候选最远的空列，整张图水平循环换列（无插值、无裁切、不复制孔）。没有共同空列时选穿过候选最少的切口，查看器会提示复核。低层 `TubeUnwrapper.process()` 仍返回标定原点的图、孔轮廓和来源图。需要固定物理角度显示时将模式改为 `fixed` 并重启控制台。历史归档不会改写。

`capture.json` 的 `unwrapped.panorama_seam.cut_x` 是**当前输出宽度**下，显示第 0 列在标定图中的原列：`x显示 = (x标定 − cut_x) mod 宽度`；`y` 不变。相机原片、标定相位和输出尺寸不变。旧归档无该字段按 0 处理。避让的是已识别的候选，漏检/未知孔不保证避开。

**独立 YOLO 复核（不阻塞采集、不重新训练）：** 在项目根目录，用装有 Ultralytics/PyTorch 的检测环境执行。输入为干净的 Mono8 展开 PNG，输出必须是一个新目录：

```powershell
python -m tools.detect_pipe_holes 'D:\数据\某批次\unwrapped.png' --output 'D:\复核\某批次'
```

默认使用本项目 `models/pipe_hole_yolo11n_v2_1/weights/best.pt`。复核会读取同批次切口记录，回到固定角度网格做重叠切片，最后把坐标映回展示图。相邻切片的完整框优先；只有边缘预测且没有完整框印证时不会直接丢弃。结果为 `detections.json`（一孔一个 ID）与整图预览 `detections.jpg`，框坐标为右/下不包含的像素边界。跨圆周边界的一个孔即使要画两段也只计一次，并附无框的环绕局部 PNG。

旧展开图如需在没有四路原片时另存避边版本，可附加 `--recenter`：按已合并的检测框重新选切口，输出无叠框的 `unwrapped.png`，JSON 和预览均对应该新图。`cut_x` 为相对标定原点的总偏移，`additional_cut.cut_x` 为相对本次输入 PNG 的偏移。不知道原始标定起点的独立 PNG 以输入的第 0 列为基准。可选 `--conf`、`--device`、`--batch`；默认置信度 0.40 不是现场验收阈值。实时控制台的 `hole_candidate_count` 是光学候选数，不是 YOLO 孔数。

## 文件说明

- `index.html`：控制台界面
- `styles.css`：工业深色视觉样式
- `app.js`：前端状态、预览和参数交互
- `server.py`：本地 HTTP API 服务
- `hikrobot_camera.py`：海康 SDK 枚举、连接、取流、触发和保存
- `image_codec.py`：Mono8 BMP 预览、裁切缩放和 PNG 保存
- `tube_unwrap/`：`tube_unwrap 0.1.2` 四视角圆柱展开源码
- `tube_unwrap/hole_blending.py`：新版孔洞轮廓保护和局部融合
- `tube_unwrap_bridge.py`：采集图像到展开算法的适配层
- `tube_unwrap_recipe.json`：四路相机横向标定、相位和展开输出参数
- `diagnose_cameras.py`：相机枚举诊断工具
- `settings.json`：运行后自动生成的参数文件
- `captures/`：默认图像输出目录
